# Правила работы (Workflow)

## Главное правило
**Одна задача — одно изменение.** Не смешивать несколько параметров в одной правке (weight, height, padding, aspectRatio — не всё сразу).

## Перед задачей
- Проверить `git log --oneline -5` — на каком коммите работаем.
- Проверить `git status` — нет ли незакоммиченных изменений.

## Во время работы
- **Точечные правки.** Один параметр за раз.
- **Не верить «сделано» на слово.** Проверять на устройстве (скриншот, координаты).

## Если 2–3 итерации не дали результата
- **Стоп.** Не давать третью правку «на глаз».
- **Показать только проблемный фрагмент кода** (не весь файл) — тот `Box`/`Column`/`Modifier`, который относится к задаче.
- Объяснить словами, как понимаешь текущую структуру.
- Спросить: «Что именно не так? Куда смотреть?»

## Отчёт после задачи
- **Краткий:** что изменил (1–2 строки), где (файл), результат сборки (успех/ошибка).
- **Не присылать весь код** — только если это нужно для разбора.
- **Не присылать длинные объяснения** — только суть.

## Коммиты
- По команде «коммить».
- Сообщения на русском, формат «тип: краткое содержание».
- Перед коммитом — сборка `./gradlew assembleDebug`.
